* PROTOCOL — how this file enlivens
:PROPERTIES:
:ID: nav-protocol
:END:

Every entry below is a *hotpath*: an intent, its keywords, and the exact place
in code where the action is. This file does not instruct — it dispatches.

- *Search it*: =emacsclient --eval '(dojo/nav "epoch")'= matches headings and
  =:KEYWORDS:=, returns =(heading path keywords)=. Or plain =Grep= this file —
  keywords are chosen as the words you'd guess.
- *Fire in parallel*: lookups are independent — batch =dojo/nav= + =LSP= +
  =Grep= calls in one volley, never serially.
- *Jump*: =:PATH:= is =file= or =file::symbol=. Feed the symbol to LSP
  (documentSymbol/findReferences) once you land.
- *Vitality, not staleness*: every =:PATH:= is machine-checked by
  =scripts/nav_verify.sh= and =(dojo/nav-verify)=. A *Stop hook* runs the
  check when a session tries to end: changes are what break hotpaths, and the
  session that made the change has the context to mend the map most
  succinctly — it is blocked from stopping until the entries are true again.
  An entry that rots gets fixed or culled, never trusted. When you add code
  worth finding, add its hotpath in the same change.

** tool decision tree — locate vs. harvest vs. symbol-work
:PROPERTIES:
:ID: nav-tool-decision-tree
:KEYWORDS: grep read lsp dojo-nav bridge decision tree when which tool locate harvest
:END:
Learned by REFLECT: the three lookup tools are not interchangeable. Choose by
the *shape of the question*, not by habit.

- *Locate code* — "where does X live", "which files use X", "where's the boot
  tree": *Grep + Read first*. Fastest, no cold-boot risk. This is the default
  and wins on nearly every discovery count.
- *Harvest links* — only when *authoring* a constellation-anchored doc and you
  need a canonical =[[id:...]]= or a reusable =:ID:=: =dojo/nav= /
  =dojo/section-for-module=. The bridge earns its keep for writing, not finding.
- *Symbol-precise work* — rename, find-references, type/hover, exact
  definition: *LSP*. Not for file-level "where does X live".

In short: Grep/Read to find, the bridge to cite, LSP to operate on a symbol.

** the prose walk — ONE geometry, every reader a view
:PROPERTIES:
:ID: nav-outline
:KEYWORDS: outline prose walk meadow cell fence headline phase path findProse findCells findMeadows inMeadowRange fold state machine one grammar name coord cellIdentities identity frame key duplicate collision
:PATH: assets/js/turtling/parse.js::export function outline
:END:
A FOLD over [[id:nav-classify]], never a walk of its own — it reads roles, not
text, because the fences were already named once.

*A CELL'S IDENTITY RIDES THIS WALK* (D024). Each cell carries =name= — the word
on its opening fence, the author's own — and =coord=, its place in the tree: the
section-index chain, then its order among its own section's cells.

*A NAME IS NOT THE IDENTITY; THE ID IS* (rule 4′). Two things, two jobs: =name=
is a LABEL, free to repeat under different phases and displayed as she wrote it;
=id= is the frame key — the section chain, then her word or this cell's ordinal
(=1.2.myname=, =1.2.3=). So the same word under two subheadings is two cells and
no wound; twice in ONE section is one place claimed twice, and that is a real
collision. Titles never enter the key (prose changes freely; the tree's SHAPE is
the structure), and every cell takes an ordinal slot whether named or not, so
naming one never re-keys her sisters.

=cellIdentities(cells)= spells the rule ONCE — =id=, =name=, =named=, =collides=,
=why= — because two readers want it: the seating law keys frames on =id=, the
diagnostics query turns =collides= into a wound (=why= picks the sentence). A
name may not be spelled as a PLACE (=/^\d+(\.\d+)*$/=): =1.2= as a word would key
the frame that SITS at 1.2, and a duplicate check watching names alone could
never see it — the grammar is refused so the class dies, not the instance.

*Bounded, not immortal.* A SECTION opened above re-keys everything beneath it,
named or not: nothing survives a restructuring, and rule 4′ chose reusable names
over immortal ones. What this replaced (=#cellN=) was worse in kind — it made
every cell a neighbour of every other, so opening one in chapter one re-aimed a
running figure in chapter nine.

=outline(lines)= → ={ meadows, cells, phases }= is THE walk over prose space
(=cmp-vet-4=). It takes LINES, because a line is the one thing both a tree and
a CM6 doc already have — text in, shape out, pure. Every reader is a view:
=phaseCells= (nodes + vocabulary), =phaseAt= / =cellAtLine= (the phase,
D021), and the editor's =findProse= / =findCells= / =findMeadows= /
=inMeadowRange= / the fold services (=plang-mode.js= is now only the CM6
adapter). Three hand-rolled copies of this machine used to agree by luck;
=lit_tokenizer_test.mjs= pins the two sides as one answer. The healing marks
(=implicit=, =meadowCloseImplicit=, =info=) keep =printAST= round-tripping
exactly, which is what the line arithmetic rests on.

*** two addressings, one seam (=cmp-vet-4=)
A LINE addresses an INTENTION — where the reader is; total (prose has one) and
local, so it crosses surfaces (=scene.attend(addr, line)=) and the wire, and the
page law resolves it once (=law.attend= → =cellAtLine=). A KEY names a BODY for
one evaluation — the frame key; re-derived each parse, crossing nothing. A line
would be worse there: any edit above a cell would move its key and restart a
running figure. That key is the cell's NAME, or its tree coordinate when unnamed
(D024, [[id:nav-outline]]) — never a flat ordinal, which had the same disease a
line has, only quieter. Pinned by =weave_page_test.mjs= ⊗ =scene_seam_test.mjs=.

*** the hatch carries the fault — no runtime on the watcher (D020 amended)
*=state= is the DOCUMENT's health; =diagnostics= are the addressed wounds.* Any
standing WALK wound makes =verdict= answer =error=, with a LOCATED message
(=Arrowhead › wow › wow · line 7 — …=, via =spokenWound=). It used to answer
=error= only for the buffer's OWN key, so a page whose CELL died reflected
=success= with a null message — and =outerSignal= carries exactly ={state,
message}=, so a FOLLOWING watcher was told nothing. Only a DRAFT showed it,
because a draft RE-RUNS the friend's code on her own canvas: runtime standing in
for a fact the author already knew and had already sent. Appearance still rides
the diagnostic's ADDRESS, never this binary, so healthy cells keep their light.
A parse error is still not a death (=kind: "walk"= only).

*FACTS AND WORDS ARE TWO LAYERS.* =weave/queries.js= is the QUERY — gather,
locate, judge — and it authors no prose: a wound it makes carries the facts for
a sentence (=why=, =word=, =answersTo=, =standsOn=), never the sentence, while a
wound it passes through keeps the words it was GIVEN (the parser's, the
canvas's), quoted and never rewritten. =weave/wound-view.js= is the VIEW, and
the only place facts become words: =placeOf= (where it hurts), =describe= (what
hurt — quoted where given, composed where not), =sayWound= (the whole sentence).
Every surface renders through it — the core HUD, a friend's panel, the editor's
gutter (=toDiagnostics= → =describe=), and the reflect's =message=, which the
authoring surface says BEFORE the wire so the server carries words it never has
to interpret (D022). =verdict= answers ={ state, wound }= — WHETHER and WHICH,
never how it reads. They were one module and the query grew a =message= field
that was sometimes quoted and sometimes its own composition, with nothing
telling a reader which. Pinned by =test/js/wound_view_test.mjs=.

*The turtle's fault channel is a LIST, never a sentence.* =renderstate.meta=
carries =diagnostics= — abstract wounds (address ⊕ span ⊕ message ⊕ kind) — and
=upsertAmbient= answers ={ success, wounds }=. It published
={ state, message: errors[0].message }=: an arbitrary pick (a second selector
beside =primaryWound=), the other wounds discarded, and a receiver handed a
STRING it could only reprint. A sentence has no address, so nothing could be
isolated. The wounds ride the SAME field the reflect uses, so there is one
channel: the turtle's are abstract, the reflect's are the same wounds LOCATED,
and locating is an ENRICHMENT, never a second type. A throw is a wound too.

*The wound is isolated to its CELL, and to the cells that stand on it.*
=weave/queries.js= gathers FOUR kinds in one shape — =parseWounds= (the tree's
broken statements), =ailmentWounds= (the canvas's walk faults, each keeping the
address of the frame that died), =nameWounds= (D024 collisions), and
=dependentWounds= — then =locate= names every one's phase, cell and line in a
single prose walk. Breaking them apart is what let the fourth exist without
growing the function.

*Dependents are D019's edge, walked BACKWARD.* =feedsVocabulary(sourcePath,
targetPath)= is the one predicate: =phaseCells= walks it forward to build a
cell's vocabulary, =dependentsOf(cells, i)= walks it backward to find who a dead
cell leaves standing on a definition that never ran. They are compromised
WHETHER OR NOT THEY HAVE RUN — a page seats lazily, so otherwise the child
learns it only by reaching each one and watching it die. Marked
=kind: "dependent"=, =severity: "warning"= (the existing =toDiagnostics=
severity does the rest — no new machinery), addressed to the DEPENDENT's own
cell key via =cellKey=, and skipped where a cell already carries its own fault.
