:END:

From the repository root:

#+begin_src sh

#+end_src

The script uses the real parser, scheduler, law/admission path, and headless
compositor/materializer. It records:
- A healthy authored wait before and at its due time.
- An ended figure with a living waited child.
- Capacity-one credit pressure before/after draining.
- A controlled delayed admission before and after its reply.
- Finite constructions with 600 and 12,000 admitted motions.
- An ended-owner child constructing after a wait.

The compositor fixtures use a fixed allowance of four synthetic clock units.
Each identity-admitted motion charges one synthetic unit. This deliberately
models cost; it measures neither actual milliseconds nor browser/GPU latency.
Opportunity timestamps are an independent declared sequence. No random inputs,
browser, new packages or network services are involved.

A state record is a snapshot before its following drain unless the phase explicitly
says after-credit-return. Read the frame records, not only top-level booleans.
Termination records mark unfinished fixtures as censored; the observation window
is not a truth ceiling. A censored long-lived fixture is not automatically a failure.

The manifest hashes JS sources, the shared harness and the instrument, and records
both repository HEADs plus dirty runtime paths. The checkout is dirty: HEAD alone
does not identify the program observed. Full file-hash manifests detect drift;
reproducing a historical dirty state still requires those source versions.
Raw records carry fixture text and settings.

* P0/P1 learnings — what to do
:PROPERTIES:
:ID: live-rendering-learnings
:LENS: experimentalist
:END:

P0 and P1 are done. Their result is a rejected gate and a narrower next intervention,
not permission to ship slowdown. Evidence: [[id:live-rendering-p1-results]] and
[[id:live-rendering-stopwake-results]].

1. *Repair the narrow false premise.* Preserve the ended-owner witness as a regression;
   traverse through ended ancestors in =atCut=. Do not equate that repair with readiness:
   a closed due body or queued derived move can still require work.
2. *Carve by authority, not vocabulary.* Ask existing owners for their own facts:
   admission pending/ready; channel credit and owed-deposit repayment; derived move
   queued/consumed/committed; run live/failed/retired. Wake is not suspension-clear;
   clearing can mean death. Queue consumption is not proof of a commit.
3. *Earn the gauge first.* Collect across the actual transition window, prove detection
   with a positive control, and read the resulting pose. Getter names, absent verbs
   and zeros outside collection are not observations of eligibility.
4. *Keep the reference reader, not its architecture.* Use the O(frames) scan as an
   experimental oracle. The observed seams are incomplete; an O(transitions) account
   is not disproved. No second dependency graph or universal wake class is earned.
5. *Re-test one exposed fact at a time before changing H.* Then repeat fixed-question
   pairs: same work allowance and sink, canonical meaning equal, healthy waits advance,
   held intervals create no catch-up debt. Synthetic work is not browser latency.
6. *Respect the remaining boundary.* Residency and driver idle/new-play need separate
   witnesses before live integration. After a trustworthy gate, test drawable coherence
   (P2), replacement lifetime (P3), accounting (P4), then candidate invariance (P7)
   before browser attribution and viewer trials (P5/P6). Replay stays deferred.

Method to keep: predict first; change one cause; retain contrary and censored results;
repeat; conclude only what the instrument can establish. Existing green tests are a
regression floor, not evidence that an unimplemented policy works.

* First next action
:PROPERTIES:
:ID: probe-live-rendering-next
:END:

The reference traversal catches the ended-owner defect, but closure alone also
misses a queued derived move and a due closed body. The due-frame gate passes
finite horizon pairs yet retries unanswered admission without a wake and requires
O(frames) scanning. [[id:live-rendering-p1-verdict]] rejects promotion.

The stop/wake isolation reads the existing seams: stops are partly visible, wakes are not,
and a "wake" is not one thing ([[id:live-rendering-stopwake-results]]). This does not rule
out an O(transitions) account of other seams. Before any runtime change, have each owner
report the fact it owns — admission verdict, channel capacity/credit, place commit, run
liveness. Residency and true driver idle/new-play still need witnesses. Do not rescue an
ambiguous gate with another graph.
The owner census reports each owner's stop and eligibility: no owner routes its eligibility
change, and the residency witness is now earned ([[id:live-rendering-owner-census-results]]).
Driver idle/new-play still needs a witness.
P2–P7 treatment work is explicitly gated, not silently declared complete.
