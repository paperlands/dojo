#+PROBE-STATUS: concluded

* Predicted before the run
:PROPERTIES:
:ID: probe-live-observation-plan
:LENS: empiricist adversarial
:END:

Run =node probe/state-model/live-observation.mjs=. Disposable scheduler mirrors;
real parser, readouts, law gate, run authority and headless compositor. No change
to clock arithmetic, service order, admission checks, subject identity or syntax.

Cross two factors independently: (R) an installed receiver's pose participates
in figure equality / is only the live receiver cursor; (P) implicit spatial
reads of supplied peers are captured question inputs / reads through the
existing observation path at use. Temporal facets, explicit scalar arguments
and captured participant identities are not changed. P applies to all figures
in its mirror as a deliberately broad challenge, not a proposed default.

- Separate receivers: one step each, finish. Shared receiver: prediction R
  stops mutual renewal *and* retains both steps (not just quiet by dropping one).
  Across a wait and noncommuting steps, continue from the accepted pose rather
  than a private cursor. Reverse source order is a challenge to confluence.
- Pursuit: R alone leaves schedule-dependent implicit peer reads. P may make
  accepted trajectories cadence-invariant; equality includes logical cuts and
  full pose traces, not just endpoint or run count. Equal traces with no actual
  observation or a silently skipped movement do not qualify.
- Hand against a waiting receiver: R keeps the same run and elapsed wait, and
  continues from the new accepted pose. An explicitly supplied receiver y
  should still replace even in R+P. Hand against a peer: a read before the
  hand cannot change retroactively; a later live read should see the new y.
- Pending attempt: change a read participant while a motion answer is awaited.
  Live observation is not permission to publish the old candidate. An old reply
  after source replacement must not write even in R+P.
- Constrained receiver: a prohibited step should not land merely because
  its continuation can now read the live receiver. A pure named figure that
  draws from a participant's pose should expose what broad P costs after its
  run has completed; that is a different promise from executing a behaviour.

Stop at the first unsupported claim; retain negative observations. This is
not a selection of authoring rules, feedback resolution, or a new engine.

* Falsifiers: retaining a run does not retain a valid attempt

Park an actual =faceto= reply while fox starts at (0,0,0) and prey is at
(0,5,0). Accept a hand edit, then release the old reply.

| Edit while pending | Subject form (=faceto prey=) without restart | Point form (=faceto prey.x prey.y=) without restart |
|-------------------+-----------------------------------------------+-----------------------------------------------------|
| Prey moves to (0,-5,0), P | no base revision on attempt: old reply accepted, fox ends (0,+3,0) | stale reply rejected; same run retries and reaches (0,-3,0) |
| Fox moves to (10,0,0), R | old reply accepted and writes fox back to its old origin; then (0,+3,0) | stale reply rejected, but retried request still starts at (0,0,0); final (0,+3,0) again |

Existing restart gets both edits right in these fixtures: the changed question
fences the pending reply and the new run inherits the accepted receiver pose.
For a peer-only change the existing coordinate form captures and validates a
configuration revision and already has bounded reread/retry. For a receiver
change that guard is necessary but insufficient: the next attempt takes a
fresh observation while the executor's local pose is still the old one.
The tested =wait= resume path refreshes that pose; retry currently does not.

Source replacement with a reply outstanding leaves the old installation
absent, publishes none of its commands, and leaves the new fox at (20,0,0) in
all four arms. Lifetime/authority survived this control. The two red cases
above do not require a retired writer or a broken geometric law: both bad
moves pass the standing law gate.

* Disposition
:PROPERTIES:
:ID: probe-live-observation-disposition
:LENS: architect
:END:

Keep two distinctions, not a global switch: a question defines what answer
must be rebuilt; a use-time observation feeds one attempt. And a live run
does not make either a past read or a private cursor current. Blanket P loses
derived-figure redraw; blanket R loses an accepted hand move. No production
landing. The next bounded comparison can ask whether observed commands can
build a fresh attempt from one accepted cut (target read AND receiver cursor)
without reviving retired state, resampling earlier admitted input, or changing
the already-working wait continuation. Do not add a scheduler-wide era or
restart on every motion to solve an attempt-local problem.
